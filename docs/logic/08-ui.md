# 8. UI behaviours, layout and accessibility rules

## Visual system
Single file, no framework, no build step. Font Public Sans (Google Fonts). The CSS (first `<style>`, ~1,200 lines) starts
with a design note ("VOICE: a builder's working ledger, calm and exact, like the EliteCraft statements"). Light and dark
themes via `prefers-color-scheme`; navy `#14263d` / teal `#0d7a75` accents; report pages imitate the printed investor
statement (navy header band "ELITECRAFT / REAL ESTATE"). Later story CSS lives in named blocks just before the last
`</style>` (Scope A, Scope B, upgrades, to check, QA sweep…). After any CSS merge check the brace balance is 0.

## Standing UI rules (apply to every change)
* **Checkboxes**: only the box itself is clickable, never the label text (global handler). Make boxes bigger for touch.
* Mobile **and** desktop: test at 375, 390, 768, 1300 (and up to 1440), light + dark. No horizontal scroll, rows aligned
  with and without optional content, **no truncated money** (inputs grow / wrap; "$ 797,0(" is a bug), tap targets
  ≥ 44 px on phones, money inputs show commas.
* Same unsaved-changes popup style (Save / Discard / Go back) wherever unsaved state can be lost.
* Don't change calculations / data / saving / Sheets logic unless the story requires it; additive data changes only.

## Layout highlights
* **Header** (`header.top`): brand, project picker or budget picker, save state chip, Save for team; tabs strip
  (Inputs, Builder + investor, Investor report, Builder report, Budget, To check with open count). On phones the header is
  compact and the tab strip scrolls horizontally (active tab scrolled into view).
* **Inputs**: two columns on desktop (form + sticky sidebar with builder profit on top, investor profit box at the bottom),
  one column on phones with a sticky mini summary. Multi-input rows (short loans, draws, extras, investors, lot loans) stack
  into a tidy 2-column grid on phones with labels above and a small aligned × button. From/to month inputs are one grouped
  control. Seg controls don't wrap awkwardly.
* **Budget**: toolbar rows wrap cleanly on phones (full-width selects, button grid). The table fits at ~1300 px even with
  upgrades + invoices shown (Notes not cut off); on phones rows become cards (name, amounts, Finished, invoices button).
* **Backups window**: list of restore points with date, source and one clear primary action per row; restore asks first.
* **Modals**: focus moves into the dialog, Tab is trapped, focus returns to the opener on close, Esc closes (with the
  unsaved-typing guard). Busy overlay `#busy` during save/backup.
* **Toasts** (`#toasts`, bottom 16 px): max 3, ok 5 s, warnings 8 s, dismiss ×. `status(text)` picks warn styling from
  the wording.
* **Keyboard**: after re-renders focus returns to the same control (`focusKey`/`refocus`).
